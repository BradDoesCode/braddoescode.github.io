How I built it

I build this site with Claude Code, Anthropic's coding assistant. Claude Code wrote the code for this site. I chose what to build, judged the designs and reviewed what came back.

It is a static site made with Astro. I build it on my own machine and publish the built files to GitHub Pages. I decide what is published, and I publish it myself.

The instructions Claude Code follows for this site are in the public repository on GitHub (opens in a new tab). They are a CLAUDE.md file, plus written rules and skills in the .claude folder. The written rules came before the site's code.

The facts about my career come from me. Claude Code is told not to invent details to fill a gap.

What every change goes through

Before anything is published, I run one command on my own machine, npm run check. It runs these stages in order and fails if any of them does.

  1. Type checks on the code.
  2. The build, and the CV PDF made from the built CV page.
  3. Output checks on what was built: the security policy on each page, no inline scripts, safe links to other sites, the colour contrast tables, and no personal contact details in the CV PDF, among others.
  4. HTML validation of every page.
  5. Internal links, including links to a place within a page.
  6. Accessibility against WCAG 2.2 AA, the web accessibility standard, in both light and dark colours.

Writing goes through two more checks before it is published. One checks the claims are true and credit the team fairly. The other checks that nothing private about my employer's work has slipped in. Then I review the change and decide whether it ships.

Design

The body text and headings are set in Newsreader. My name and a few display lines are set in Cormorant Garamond. Both fonts are served from this site, not from anyone else's.

The colours are navy ink with an ochre accent, in light and dark.

Motion is kept light. Sections slide in as you scroll, in browsers that support it, and links sweep to a new colour when you hover over them. Both are done in CSS alone, and both switch off when your device asks for reduced motion.

Colour and readability

The tables below show how much each pair of colours on this site contrasts, in light and dark. The ratios are worked out from the site's own colours whenever the site is built, so the numbers cannot drift from what you see.

Contrast compares how light two colours are. It runs from 1:1, no difference at all, to 21:1, which is black on white. The Web Content Accessibility Guidelines (WCAG) ask for at least 4.5:1 for normal text, and 3:1 for large text and interface parts such as the chart bars.

Contrast matters because it keeps text readable for people with low vision, on dim or cheap screens, and in bright sunlight.

I compared six palettes, in light and dark, using Realtime Colors (opens in a new tab) to see each one on a full page, and chose navy with an ochre accent. You can see the chosen palette on Realtime Colors (opens in a new tab).

Privacy and performance

This site does not track you. It sets no cookies, has no analytics, and loads nothing from other websites.

It sends no JavaScript to your browser: the pages are plain HTML and CSS.

Links to other sites open in a new tab, and say so, including to screen readers.

Lighthouse is a tool that scores a page out of 100 for performance, accessibility, best practices and SEO (search engine optimisation). I ran it on my own machine against the built site, on every page except the page-not-found page. The scores below are for its mobile settings, and its desktop settings gave the same scores.
